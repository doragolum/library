# «Моя бібліотека» — інструкції для Claude

Особистий вебдодаток для обліку книг, бажанок і замовлень. Користувачка одна, спілкування й інтерфейс українською. Пояснюй просто, без жаргону, на «ти» (жіночий рід): вона часто працює з телефона.

## Навіщо додаток (пріоритети)
1. **Зареєструвати бажанку чи замовлення за секунди**: скриншот анонсу/замовлення, посилання, текст чи голос → готова картка → «Зберегти».
2. **«Отримала» → книга в бібліотеці** з автозаповненням (жанр, серія, полиця), перевіркою дублів, також для цілого замовлення.
3. **«Що почитати?»**: опитувальник (одиночна/серія → жанр/тропи/настрій → мова → обсяг), недочитані серії.
4. Статистика, полиці, план читання, фінанси — бонус, не основний інтерфейс.

## Архітектура (з 14.11.2026)
Історія переходу — `ПЕРЕХІД_SUPABASE.md`.
- **Дані:** база Supabase (проєкт `syrwtxxgbybftkuxuvlq`, регіон ЄС, безкоштовний тариф). Структура — `supabase/migrations/`:
  - `books` — одна книга = один запис на весь шлях: `stage` = `wish` → `ordered` → `ttn` → `shipped` → `delivered` → `library` → `sold` / `gifted`. Для бажанок `wish_kind` (Хочу купити · Докупити серію · На майбутнє). Окремих «Бажанок» і «Обліку бібліотеки» більше немає: сайт отримує їх як два списки (`wish`, `books`) з `api`.
  - `series`, `catalog` (дані видань за ISBN, з джерелом), `wish_found` (знахідки для бажанок без ISBN), `log` (журнал змін), `kv` (службові стани: `options`, `goals`, `shelf_marks`, `news`, `bot_pending`, `id_seq`, `import_token` тощо).
  - RLS увімкнено без політик: усе ходить лише через функції.
- **Функції** (`supabase/functions/`, Deno/TypeScript; спільне — `_shared/`):
  - `api` — API сайту: ті самі назви дій і та сама відповідь, що колись у `doPost` Apps Script (`{fn, args, initData, key}`), перевірка ключа `?k=` або підпису Телеграму. `lbApiData` віддає все одним запитом.
  - `ai` — усе, що питає Gemini чи шукає в інтернеті: скриншот / текст / голос / посилання → картки, жанри, тропи, перевірка серій, новини серій, обкладинки.
  - `bot` — Телеграм-бот на вебхуку: пошук «чи є в мене», `/week`, `/month`, `/kyiv`, `/rotterdam`, `/streak` (серія читання з кнопками), `/help`, скриншот / посилання / голосове → картка «У бажанки / Замовила». Відповідає лише їй (`LB_TG_USER_ID`).
  - `daily` — нагадування (~10:00 за Києвом, 9:00 у Роттердамі; з 16.11), вечірнє нагадування про серію читання (`job:"streak"`), ніч (вийшли з друку → «Є у продажу»), новини серій щопонеділка.
  - `np` — Нова пошта: щогодини перевіряє ТТН, етап лише вперед. «В бібліотеку» книга не переходить сама — лише кнопкою «Отримала».
  - `enrich` — каталог за ISBN (MEGOGO → Goodreads), дописує лише порожні поля.
  - `wish-fill` — бажанки без ISBN: шукає за назвою й автором (MEGOGO → Yakaboo), певні збіги записує в порожні поля, сумнівні лише підказує.
  - `export` — нічна копія бази для Google-таблиці «Книги — копія з бази» (лише читає).
  - `import-sheet` — разове копіювання з таблиці. **Більше не запускати** (після переходу відмовляє сама).
- **Розклад (pg_cron → функції):** `lb-remind` (`0 7,8 * * *` UTC, функція сама шле раз о ~10:00 за Києвом), `lb-streak` (щогодини), `lb-night` (01:00 UTC), `lb-news` (понеділок 03:00 UTC), `lb-np` (щогодини, :15), `lb-enrich` (кожні 5 хв), `lb-wish-fill` (щогодини). Тригерів Apps Script для цього більше немає.
- **Сайт:** GitHub Pages — https://doragolum.github.io/library/ (цей репозиторій). Відкривається за особистим посиланням `?k=…` або як Телеграм-міні-додаток. `&db=0` — стара таблиця (лише для порівняння).
- **Apps Script** лишився тільки як проксі для розпізнавання тексту через Google Диск і пошуку за ISBN (`lbApiOcr`, `lbApiLookup`) та для нічної копії в таблицю (`LbExport.gs`). Google-таблиця «Книги» з додатку більше не оновлюється.
- **Джерела даних про книги:** MEGOGO Books (перше), Yakaboo, Книгарня Є, Goodreads; обкладинки — Goodreads / Google Books / Open Library.
- **Gemini** (лише безкоштовний тариф): скриншоти, голос, жанри, тропи. Пошук Google через Gemini на безкоштовному тарифі недоступний (429), тому «Новини серій» беруться з MEGOGO.

## Структура файлів репозиторію
Корінь репозиторію — це сайт на GitHub Pages.

**Сайт (корінь):**
- `index.html` — увесь сайт одним файлом: вигляд, стилі й логіка. Головний файл для змін інтерфейсу.
- `config.js` — `window.LB_DB = true`, адреси функцій `api` і `ai` (`LB_API_URL`, `LB_AI_URL`).
- `manifest.webmanifest`, `sw.js`, `icons/` — сайт як додаток на телефоні (PWA). `start_url` навмисно не задано, щоб значок відкривав адресу з особистим `?k=`. `sw.js` спершу бере мережу й не кешує запити до API.
- `README.md`, `robots.txt`, `.nojekyll`, `CLAUDE.md`.
- `ЗАВДАННЯ_v8.md` — план етапів 1–5 (усі зроблені) і що лишилось.
- `ПЕРЕХІД_SUPABASE.md` — як і коли перейшли на базу.
- `ОНОВЛЕННЯ_vN.md` — інструкції до старих релізів Apps Script (історія).

**База (`supabase/`):** `migrations/` (структура, крони), `functions/` (див. вище).

**Apps Script (`apps-script/`) — історія.** Копії старого коду; більшість функцій уже не працює (їх замінила база). Живі лише OCR / ISBN і `LbExport.gs`.
- `LibApp.gs` — сервер додатку (префікс `lb` / `LB_`). Основні частини:
  - сторінка й API: `doGet` (сторінка `LibPage` всередині Apps Script), `doPost` (список дозволених функцій `API` для сайту), перевірка доступу `lbAuth_` (ключ `?k=` або підпис Телеграму);
  - читання й запис таблиці: `lbReadAll_`, `lbApiUpdate` / `lbApiSave`, `lbApiAddBook`, `lbApiAddWish`, `lbApiDeleteWish`, `lbApiDeleteBook`, `lbOrderSave_` (замовлення → бажанки), журнал `lbLog_`;
  - Gemini: `lbGemini_`, `lbGeminiModels_`, розпізнавання скриншотів `lbApiOcr` / `lbApiAi`, жанри `lbApiGenre`, тропи `lbApiTropes`;
  - дані про книги: MEGOGO (`lbFromMegogo_`), Книгарня Є (`lbFromBookYe_`), обкладинки Goodreads / Google Books / Open Library (`lbFillCovers`), автозаповнення порціями `lbAutoFill`;
  - «Новини серій»: `lbSeriesNews`, `lbApiNews` (лише пропозиції, зберігаються в `LB_NEWS`);
  - Телеграм: `lbTelegramConnect`, `lbBotPoll`, кнопки й фото в боті;
  - нагадування: `lbInstallReminders`, `lbDailyReminders` (релізи, «ще не відправили», тиждень/місяць, Київ);
  - нічні роботи: `lbNightly` (сортування, `lbCleanWish_`, `lbWishOnSale_`, обкладинки);
  - видавництва (v8): довідник `LB_PUBLISHERS` («правильна назва» ← варіанти), `lbPubCanon_` — підставляється всюди, де видавництво приходить з інтернету чи записується; `lbPublishersPreview` / `lbPublishersApply` — виправлення в таблиці;
  - дата замовлення (v8): колонка «Дата замовлення» в «Бажанках» (`lbAddOrderDateColumn`), ставиться сама при статусі «Замовлено»;
  - етап 3 (v12): колонки «Оригінальна назва», «Джерело» (бібліотека й бажанки) та ISBN у бажанках (`lbAddIdColumns`); дублі за ISBN (`lbIsbnKey_`, `lbFindIsbn_`); назви томів замість «Частина N» (`lbVolumeTitlesPreview` / `lbVolumeTitlesApply`, MEGOGO → Goodreads); перевірка серій на MEGOGO `lbApiSeriesCheck` (кнопка «🔗 Перевірити серії й авторів» у Бажанках); тест `lbTestVolumes`;

Листи не об'єднуються (вона обрала варіант Б, щоб не зламати меню й НП); «Продані» лишається окремим листом;

- `LibPage.html` — та сама сторінка для відкриття прямо з Apps Script (`doGet`). Це **старіша копія** `index.html`: останні зміни інтерфейсу є лише в `index.html`. Головна адреса — сайт на GitHub Pages.

Основну таблицю не чіпає. З v15 тут же перемикання на базу: `lbSwitchToDb` (вимикає `lbBotPoll`, `lbDailyReminders`, `lbNightly`, `lbSeriesNews`, `lbAutoFill`, ставить webhook бота на функцію `bot` у Supabase) і відкат `lbSwitchBack`.

## Як випускати зміни
- **Сайт:** коміт у `main` → GitHub Pages оновлюється сам за хвилину-дві. Вона хоче, щоб погоджене одразу йшло на сайт.
- **Функції бази:** спершу коміт і push, потім розгортання через MCP маленьким `index.ts`, що імпортує код із репозиторію, закріплений на коміті:
  `import "https://cdn.jsdelivr.net/gh/doragolum/library@<sha>/supabase/functions/<name>/index.ts";`
  Перед розгортанням перевір `git diff <старий sha> <новий sha> -- supabase/functions/<name> supabase/functions/_shared`, щоб не викотити чужих незавершених змін.
- **Зміни структури бази:** міграція через MCP (`apply_migration`) і копія файлу в `supabase/migrations/`.
- **Apps Script** тепер змінюється рідко (лише OCR / ISBN / копія). Якщо треба: онови файл у `apps-script/`, напиши коротку інструкцію `ОНОВЛЕННЯ_vN.md` і нагадай **Розгорнути → Керувати розгортаннями → ✏️ → Нова версія → Розгорнути**.
- Наприкінці відповіді окремо напиши, чи треба їй щось робити, чи зміни з'являться самі.

## Правила
- **Ключі й токени** — лише в Supabase → Edge Functions → Secrets (вписує вона сама) або у Властивостях скрипту. Ніколи в коді, репозиторії (він публічний!) чи чаті; не проси їх у неї.
- **Масові зміни даних** — спершу список змін на погодження, «так», потім запис у журнал `log` для кожної зміни. Нічого не видаляти без підтвердження.
- **Без оплат:** не підключати платні тарифи, картки чи API з оплатою без явної згоди.
- Gemini помиляється з фактами: дані з інтернету показувати з джерелом і лише як пропозицію, яку вона підтверджує. Новини серій, жанри, тропи — лише пропозиції з кнопкою.
- «Де фізично» (`place`: Роттердам · Київ) і «Наявність» (`avail`: статус) — окремі поля. Продані й подаровані не потрапляють у фільтри місця.
- Чого не робимо: імпорт із Gmail, обхід захисту сайтів від ботів, платні тарифи, ігрові досягнення.

## Інтерфейс (погоджено 15.11.2026)
- Тексти на «ти», «Скриншот» (через «и»).
- Назва додатку на телефоні й у вкладці — **Shelfie** (16.11.2026); сам інтерфейс українською. Значок: полиця з книжками, вигнута усмішкою. Звичайний «Пастель» (`icons/`, `manifest.webmanifest`), запасний «Класика» (`icons/classic/`, `manifest-classic.webmanifest`); перемикач «Значок» у «Я» (`lb.icon` у localStorage). Джерела значків — `icons/icon.svg`. Заголовок угорі: логотип без фону (вбудований SVG, кольори з теми) + «Shelfie»; той самий логотип файлами `icons/logo.png` і `icons/logo-dark.png` (прозорий фон).
- Стиль «Папір і зелень», зелена темна тема; кольори лише через змінні (`--accent-fill`, `--field`, `--shelf-ink`, `--plate`, `--star` тощо), без окремих `prefers-color-scheme` правил.
- Без горизонтальних смуг, що гортаються вбік: фільтри й кнопки переносяться на новий рядок.
- 📍 — лише місце чи полиця. На кнопках — тонкі лінійні значки, не емодзі (скрипт у кінці `index.html` замінює емодзі сам; фільтри 📍 Роттердам / 🏠 Київ лишаються).
- Шкала шрифтів: 28 / 20 / 16 / 15 / 13 / 12 px, менше 12 — ніде. Заголовки блоків на Головній 16 px шрифтом сайту (Literata лише для назв).
- Колір за значенням: залитий зелений — одна головна дія; світло-зелений — готово / можна забирати; жовтий — скоро / в дорозі; червоний — треба щось зробити; звичайне — сірим текстом без пігулки.
- Головна: плашки «Можна забирати» (лише коли є) · «Витрачено в місяці» · «Замовлено, в дорозі» · «Релізи за тиждень»; на комп'ютері ліворуч посилки, праворуч читання. «Прочитано в місяці» — на вкладці «План».
- «Я» — коротке меню; «Досягнення» сховані. Бібліотека: Книги · Що читати · Полиці · План · Серії.

## Значення полів
- Статус читання: прочитано · не читала · читаю · закинула.
- Наявність (з v10 — лише статус): у колекції · на продаж · на розподілення · позичена · продана · подарована. До перенесення були ще «бібліотека» і «Київ» — код розуміє обидва варіанти (`lbAvail_`, `stOf`).
- «Де фізично» (кінець «Облік бібліотеки», v10): Роттердам · Київ. «Київ» — книги, що лежать у Києві й приїжджають посилкою. Позичена книга лишається там, де була до позичення. «Отримала з Києва» міняє лише «Де фізично», статус (напр. «на продаж») лишається.
- Статуси бажанок (по порядку): Хочу купити · Докупити серію · На майбутнє · Замовлено · Створено ТТН · Відправлено · Доставлено · В бібліотеці.
- Наявність бажанки: Є у продажу · Анонс · Передзамовлення · Немає у продажу · Не видана.
- «Дата замовлення» (кінець «Бажанок», v8): ставиться сама при «Замовлено»; при «Отримала» стає «Датою покупки» книги.
- Ціна 0 — безкоштовна книга (акція).
- Додаткові поля: ISBN, Обкладинка, Дата покупки, Дата початку, Дата прочитання, Оцінка, Кому/Коли позичила, Повернути до, Посилка з Києва, Планую читати, Поточна сторінка, Тропи, Враження.

## Відкриті задачі
- Імпорт замовлень із Gmail — **не робимо** (вона відмовилась).
- Дрібні зауваження — у `НАСТУПНЕ_ОНОВЛЕННЯ.md`.
